# Ускоренная очередь

Автоматическая миграция, быстрая очистка, проверка спамблока и завершение других
сеансов обрабатывают до 10 аккаунтов одновременно на чат. Освободившееся место
сразу занимает следующий элемент очереди. Ручной ввод кода остаётся последовательным.

При миграции очереди пароль 2FA из JSON используется автоматически. Если его нет
или Telegram отклонил пароль, аккаунт пропускается: бот освобождает подключения,
удаляет временные копии и продолжает очередь без запроса пароля. Исходный файл
сессии сохраняется, старая авторизация не завершается. Это пропуск аккаунта,
а не отключение или сброс его пароля 2FA. Отдельный вход по номеру сохраняет ручной ввод.

Результаты отправляются по 10 аккаунтов в ZIP. Каждый аккаунт представлен парой
`.session` и `.json` в корне архива. Для проверок результаты разных категорий
собираются отдельно. Остаток меньше 10 отправляется в конце очереди; при достижении
лимита размера архива (45 МБ) пакет может быть меньше. Повторная отправка — `/archives`.

Обновите исходники и перезапустите бота. По умолчанию работает 10 обработчиков;
если в окружении или `.env` уже задан меньший лимит, измените его:

```dotenv
CONCURRENT_WORKERS_PER_CHAT=10
```

Можно задать значение от 1 до 10; старые значения выше 10 ограничиваются десятью.
Лимит очистки диалогов остаётся 10 на аккаунт, ожидания FloodWait сохраняются.
Фактическая скорость зависит от Telegram, прокси и сервера.

Офлайн-проверка:

```sh
API_ID=12345 API_HASH=offline BOT_TOKEN=123456:offline python -m unittest discover -s tests -q
```
