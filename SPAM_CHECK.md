# Проверка спамблока

1. Нажмите «Проверка спамблока» в главном меню.
2. Отправьте `.session` или ZIP с сессиями и парными JSON.
3. Нажмите «Проверить и запустить».

Проверка работает с копиями существующих сессий, до трёх аккаунтов одновременно.
Она отправляет `/start` официальному `@SpamBot`, читает ответ и при ошибке или
неизвестном ответе разблокирует `@SpamBot` и делает одну повторную попытку.
На подключение отведено 20 секунд, на каждую попытку проверки и разблокировку —
по 30 секунд. Отмена очереди отменяет активные проверки.

Результаты сохраняются в отдельные ZIP по категориям:

| Архив | Категория |
| --- | --- |
| `spam_clean.zip` | Без спамблока |
| `spam_permanent.zip` | Вечный спамблок: явное указание постоянного ограничения |
| `spam_temporary.zip` | Временный спамблок: указан срок |
| `spam_geo.zip` | Ответ об излишне суровой реакции антиспам-системы на номера телефонов |
| `spam_frozen.zip` | Явное сообщение о заморозке или ошибка `FROZEN_METHOD_INVALID` |
| `spam_unknown.zip` | Неизвестная формулировка, ошибка, таймаут или неавторизованная сессия |

Название «по гео» используется для указанного пользователем ответа о номерах
телефонов; сам этот ответ не устанавливает страну или причину ограничения.
Отсутствие даты само по себе не означает вечный блок. Тексты на неподдерживаемых
языках попадают в «Не определено».

Архив отправляется после трёх результатов одной категории; остатки — при
завершении очереди. Внутри только `.session` и `.json` в корне, без вложенных ZIP.
Исходные JSON-поля сохраняются, добавляется `spam_check` со статусом, текстом
ответа и временем проверки. Отправленные архивы хранятся для повторной отправки
через `/archives` отдельно от результатов очистки и миграции.

Существующая база обновляется автоматически: старые архивы сохраняют категорию
`accounts`. Для применения изменений обновите код и перезапустите процесс бота.

Офлайн-проверка:

```sh
API_ID=12345 API_HASH=offline BOT_TOKEN=123456:offline python -m unittest discover -s tests -q
```
